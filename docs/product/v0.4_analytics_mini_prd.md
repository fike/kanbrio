# Analytics & Metrics — Mini-PRD (v0.4)

## 1. Functional Requirements

### FR-1: Monte Carlo Simulation
**Endpoint:** `GET /api/workspaces/:workspace_id/analytics/monte-carlo`

**Query Parameters:**
| Param | Type | Default | Description |
|:---|:---|:---|:---|
| `days` | int | 90 | Throughput history window |
| `simulations` | int | 1000 | Number of Monte Carlo runs |
| `scope` | enum | `all` | `all`, `swimlane:{id}`, `assignee:{id}` |

**Response (200):**
```json
{
  "throughput_data": [5, 3, 7, 4, ...],
  "simulations": {
    "histogram": [
      {"days": 1, "probability": 0.02},
      {"days": 2, "probability": 0.15}
    ],
    "percentiles": {
      "p50": 5,
      "p75": 8,
      "p85": 10,
      "p95": 14
    },
    "total_cards": 23
  }
}
```

**Acceptance Criteria:**
- AC-M1: Returns 400 if `days` < 7 or > 365
- AC-M2: Returns 400 if `simulations` < 100 or > 10000
- AC-M3: Returns empty throughput_data if no completed cards in window
- AC-M4: Percentiles are ordered p50 <= p75 <= p85 <= p95

### FR-2: Cumulative Flow Diagram
**Endpoint:** `GET /api/workspaces/:workspace_id/analytics/cfd`

**Query Parameters:**
| Param | Type | Default | Description |
|:---|:---|:---|:---|
| `from` | ISO date | -30d | Start date |
| `to` | ISO date | today | End date |
| `interval` | enum | `day` | `day`, `week` |

**Response (200):**
```json
{
  "columns": [
    {"id": "col_1", "title": "Backlog", "color": "#64748B"},
    {"id": "col_2", "title": "In Progress", "color": "#EAB308"},
    {"id": "col_3", "title": "Done", "color": "#22C55E"}
  ],
  "data_points": [
    {
      "date": "2026-06-01",
      "counts": {"col_1": 12, "col_2": 5, "col_3": 8}
    }
  ]
}
```

**Acceptance Criteria:**
- AC-C1: Data points sorted ascending by date
- AC-C2: Missing dates filled with last known counts (carry-forward)
- AC-C3: Returns 400 if `from` > `to`
- AC-C4: Columns ordered by position

**Implementation Note:** Requires daily snapshot table `column_card_counts` or on-the-fly aggregation from `card_transitions`. First implementation: on-the-fly aggregation. Add snapshot table in v0.5 for performance.

### FR-3: Cycle Time Scatter Plot
**Endpoint:** `GET /api/workspaces/:workspace_id/analytics/cycle-times`

**Query Parameters:**
| Param | Type | Default | Description |
|:---|:---|:---|:---|
| `days` | int | 90 | History window |
| `scope` | enum | `all` | `all`, `swimlane:{id}`, `assignee:{id}` |

**Response (200):**
```json
{
  "data_points": [
    {
      "card_id": "uuid",
      "title": "Fix login bug",
      "completed_at": "2026-06-15T10:00:00Z",
      "cycle_time_hours": 48.5,
      "assignee_id": "uuid",
      "assignee_name": "Alice",
      "swimlane": "Standard"
    }
  ],
  "percentiles": {
    "p50": 24.0,
    "p85": 72.0,
    "p95": 120.0
  }
}
```

**Acceptance Criteria:**
- AC-S1: Cycle time = time from first entry into an active (non-done) column to entry into a done column
- AC-S2: Returns empty array if no cards completed in window
- AC-S3: Percentiles computed from cycle_time_hours across all returned cards

### FR-4: Flow Efficiency & Aging WIP
**Endpoint 4a:** `GET /api/workspaces/:workspace_id/analytics/flow-efficiency`

**Response (200):**
```json
{
  "efficiency_pct": 42.5,
  "active_hours": 120,
  "wait_hours": 162,
  "total_cards": 15,
  "by_column": [
    {"column_id": "col_1", "title": "In Progress", "wait_hours": 60, "card_count": 5},
    {"column_id": "col_2", "title": "Review", "wait_hours": 102, "card_count": 10}
  ]
}
```

**Endpoint 4b:** `GET /api/workspaces/:workspace_id/analytics/aging-wip`

**Query Parameters:**
| Param | Type | Default | Description |
|:---|:---|:---|:---|
| `threshold_days` | int | 3 | Days before a card is considered stagnant |

**Response (200):**
```json
{
  "stagnant_cards": [
    {
      "card_id": "uuid",
      "title": "Fix login bug",
      "column_title": "In Progress",
      "assignee_name": "Alice",
      "idle_hours": 96,
      "idle_days": 4,
      "entered_column_at": "2026-06-10T10:00:00Z"
    }
  ],
  "stagnant_count": 1,
  "threshold_days": 3,
  "total_cards_in_active_columns": 12
}
```

**Acceptance Criteria:**
- AC-F1: Flow efficiency = active hours / (active + wait) hours * 100
- AC-F2: Active time = sum of all card-time in non-done columns where the card was being actively moved/updated
- AC-F3: Wait time = sum of card-time in non-done columns where the card had no activity
- AC-F4: Aging WIP returns cards sorted by idle_hours descending
- AC-F5: Cards assigned to done columns are excluded from Aging WIP
- AC-F6: If no cards meet the threshold, `stagnant_cards` is an empty array

## 4. Backend Architecture

```
GET /api/workspaces/:id/analytics/cfd
  └── BoardAnalyticsService::cfd(days)
       ├── Query: columns for workspace (ordered)
       ├── Query: card_transitions for period
       └── Aggregate: per-date per-column card counts

GET /api/workspaces/:id/analytics/cycle-times
  └── BoardAnalyticsService::cycle_times(days, scope)
       ├── Query: completed cards in window
       ├── For each card: compute residence time from transitions
       └── Compute percentiles

GET /api/workspaces/:id/analytics/monte-carlo
  └── BoardAnalyticsService::monte_carlo(days, simulations, scope)
       ├── Query: throughput (cards completed per day)
       ├── Run N simulations: random sampling with replacement
       └── Aggregate simulation results into histogram + percentiles

GET /api/workspaces/:id/analytics/flow-efficiency
  └── BoardAnalyticsService::flow_efficiency()
       ├── Query: active cards in non-done columns
       ├── For each: compute dwell time from transitions
       └── Aggregate active vs wait time

GET /api/workspaces/:id/analytics/aging-wip
  └── BoardAnalyticsService::aging_wip(threshold)
       ├── Query: cards in non-done columns
       ├── Compute idle hours from last transition
       └── Filter by threshold, sort descending
```
